## Project purpose

Research project comparing concept-drift detectors from `river` on streaming data, with the goal of a adaptive chunk method for SHAP-based drift detector: detailed description of SHAP-based drift detector is in `data/article/article.pdf`. MAIN GOAL OF THE REPOSITORY: implement a adaptive windowing chunk method for SHAP-based drift detector.
In `data/article/thesis.pdf` is my thesis (in Polish) describing the project and the results. The thesis is already in half done state, but it needs more experiments with SHAP and propozition of a new method focused on adaptive chunking for SHAP-based drift detection. The thesis is in Polish.

## Environment and commands

- Windows, local virtualenv in `venv/`; dependencies pinned in `requirements.txt` (`../venv/Scripts/python -m pip install -r requirements.txt`). `requirements.txt` is UTF-16 encoded (pip reads it; grep does not). No tests or linter config.
- **All scripts use paths relative to `src/`** (`../data/...`), so run them from inside `src/`:

```
cd src
../venv/Scripts/python main.py                   # run active detectors on every dataset -> ../data/results/drift_detectors_results[_N].csv
../venv/Scripts/python stats.py --csv ../data/results/drift_detectors_results.csv   # summary table per detector -> detector_stats[_N].csv

../venv/Scripts/python drift_types_plot.py       # illustrative drift-type figures (standalone)

```

Output CSVs are never overwritten: `main.py` and `stats.py` append `_1`, `_2`, … to the filename if it exists. `stats.py` asks for the CSV path in the terminal when `--csv` is omitted; `results_visualization.py` reads the un-suffixed `drift_detectors_results.csv` (hardcoded `FILE_PATH`) — change it to plot a specific run. Graphs are overwritten.

## Pipeline architecture

1. **Datasets** — `data/datasets/*.arff` (gitignored). Ground truth is encoded **only in the filename**, parsed by `parse_filename` in `main.py`:
   `Name_f_F1_F2..._p_P1_P2..._w_W1_W2..._s_S_r_R.arff` — `f` drifting features, `p` drift points, `w` drift widths (one per drift point), `s` sample count, `r` seed. `p`/`w` may be absent (no-drift stream). Target column is `class`.
2. **`main.py` / `evaluate_stream`** — builds a fresh model per dataset (`MixedNB`: Gaussian likelihood for numeric features + `BernoulliNB(alpha=1)` on one-hot nominal features; plain one-hot → `GaussianNB` saturated to P=0/1 on STAGGER/Agrawal because river's Gaussian has no variance smoothing), warm-starts on the first 100 samples, then does test-then-train. Currently only **ADWIN and KSWIN** (`seed=42`) are active, both fed `true_class_proba` (predicted probability of the true class) rather than the 0/1 error; the error-based updates and DDM/PHT are commented out. The detector-update block is the planned hook for SHAP-based signals. Detection indices are recorded as `i + 100` (absolute stream position).
   **SHAP detector (article's method, `SHAP` columns):** chunks of `SHAP_WINDOW` (L=100) records. As in the article, each chunk gets a **fresh MixedNB trained only on that chunk** and explained on the same chunk (forgetting by construction, no learning trend in S_agg); the main incremental model that feeds ADWIN/KSWIN/DDM/PHT is independent of it. `shap_explainer.StreamShapExplainer` uses `shap.PermutationExplainer` on `predict_proba` (probability space, all classes; `SHAP_N_PERMUTATIONS`=5, background = 50 warm-up rows via an `Independent` masker, `seed=42`); its `.model` is swapped to each chunk's model. It is model-agnostic: nominal features are integer-coded for the masker and decoded before prediction; the model is called through `predict_proba_many(DataFrame, classes)` if it has one (MixedNB does — vectorised, matches `predict_proba_one` to ~1e-14), else row by row. The article uses a RandomForest + `TreeExplainer`; using MixedNB + permutation is a deliberate deviation. `aggregate_shap` → S_agg per feature (Eq. 2). `shap_detector.ShapChunkDetector(B=SHAP_B=4, W=SHAP_W=2, alpha=SHAP_ALPHA=0.001)` is a streaming version of Algorithms 1–2: first B chunks = baseline, per-feature thresholds at sorted positions `round(alpha*(B-1))` / `round((1-alpha)*(B-1))` (≈ min/max), mean of the last W chunks outside them for any feature = drift, then a new baseline from the next B chunks (all features together). B=4 is the max that fits before the earliest drift (p=500) after the 100-sample warm-up. Detections are recorded at the chunk's **first** record (article: i·L); `SHAP_drifted_features` lists `record: feature, ...` per detection (` | `-separated). Cost ≈ 0.4–2 s per chunk. The timeline CSV (`record` = chunk start, `shap_<feature>`) + PNG (per-feature S_agg, true drifts, SHAP detections) go to `SHAP_DIR` (`../data/results/shap_timeline_chunk_mixednb_permutation`) and are **overwritten** on rerun; older runs live in sibling `shap_timeline_*` folders. With B=4 the thresholds are the min/max of 4 noisy values, so FDR is high (e.g. 0.67–0.93 on test streams) although the S_agg step at the drift is clean.
3. **Metrics** — `D1D2_metrics.py` holds static-style methods on class `D1D2` (called as `D1D2.tpr(...)`, no instance):
   - `get_window(tg, W)` → `[tg - W/2, tg + W/2 + 500]` (500 = detection-delay tolerance). All window-based metrics (TPR, FDR, FEDP, EDDR) go through it.
   - `D1` = mean distance from each detection to nearest true drift; `D2` = mean distance from each true drift to nearest detection.
   - `main.detection_rates` computes TPR/FDR with a separate width per drift and asserts drift windows don't overlap; `calculate_r` = `|true/detected - 1|`.
   - When a metric is undefined (no detections), `main.py` substitutes `samples_number` for R, D1, D2 as a penalty rather than leaving it null.
4. **Result CSV schema** — one row per dataset; per-detector columns follow `<DETECTOR>_<metric>` (`_detections`, `_detections_number`, `_false_discovery_rate`, `_true_positive_rate`, `_R`, `_D1`, `_D2`), plus `SHAP_drifted_features` and `Ending_Accuracy`. Columns exist only for detectors in `drifts_found` (currently ADWIN, KSWIN, DDM, PHT, SHAP). Multi-valued cells (drift points, widths, detection lists) are joined with `"; "`; when read back, pandas yields a number for single values, a string for several, and NaN for empty, so parse them with `parse_multi_value` in `results_visualization.py`. `stats.py` and `results_visualization.py` rely on this naming — keep it consistent when adding detectors or metrics. `stats.py` takes the detector list from `--detectors` (default `ADWIN,KSWIN`); `results_visualization.py` and `print_metric_arrays.py` hardcode all four (`ADWIN, KSWIN, DDM, PHT`).
5. **`stats.py` summary** — one row per detector, every cell a formatted string ready for a paper: TPR/FDR as mean with a percentile-bootstrap 95% CI (`--n-boot`, `--seed`), counts of TPR=1/0 and FDR=0/1, N for FDR, R as mean with bootstrap 95% CI over all runs and over runs with ≥1 alarm, and D1/D2 as median [Q1; Q3] over all runs plus median [Q1; Q3] and P90 over runs with ≥1 alarm. Quantiles use `method="inverted_cdf"` (no interpolation). Subsets are chosen deliberately: no-drift datasets (empty `Drift_Point`) count only toward FDR; the "all runs" D1/D2/R stats include the `samples_number` penalty values, while the "with detection" stats exclude them; FDR uses only datasets with ≥1 alarm.

## Side scripts and prototypes

- `forgetting_plot.py` — standalone (imports `main` and `shap_explainer`): on 3 sudden-drift streams (STAGGER/Agrawal/SEA, drift at 5000 of 10000) runs three MixedNB copies — no forgetting, reset at the true drift (oracle), reset on ADWIN (binary error) detection — and plots rolling accuracy (window 200) plus per-feature SHAP shares for the no-forgetting and oracle models -> `../data/graphs/forgetting/<dataset>.png` (overwritten; ~10 min total). Shows why forgetting matters: on STAGGER/Agrawal the no-forgetting model's accuracy collapses and its SHAP keeps the old concept; on SEA forgetting brings no gain.
- `adwin_different_parameters.py` — standalone: three ADWIN configs (`default`, `A` sensitive, `B` conservative) on one synthetic Bernoulli stream (`random.Random(42)`, 5000 samples, drifts at 1000 and 3000); prints detections and plots a timeline (rows = configs, dots = detections, red dashed lines = true drifts).
- `src/SHAP_example/test.ipynb` — SHAP prototype on `Agrawal_f_1_s_13000_r_8937.arff`: sklearn `GaussianNB` (LabelEncoder for nominals), `shap.PermutationExplainer(model.predict, masker=shap.sample(X, 100))`, aggregated SHAP = `np.abs(values).mean(axis=0)` per 100-sample chunk. Batch, not streaming; explains hard labels and samples the background from the whole dataset — both need changing for the streaming detector.
- `detection_methods.py` — notes only (Polish descriptions of detectors and SHAP ideas). `test_miary.ipynb` — metric experiments.
